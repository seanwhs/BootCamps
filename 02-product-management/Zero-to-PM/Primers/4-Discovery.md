# Primer 4: The Discovery Primer - Uncover Problems Worth Solving

## Overview

This primer is designed for readers who want to master the **discovery phase** of product management. This is the foundation of everything else—get discovery wrong, and nothing else matters.

**Purpose:** To give you a complete, actionable framework for discovering user problems that are actually worth solving, in 15 minutes.

## 1. What Discovery Is (And Why Most Teams Get It Wrong)

### The 30-Second Definition

> **Discovery is the process of understanding user problems, needs, and motivations before building solutions. It answers the question: "Are we solving the right problem?"**

### The Discovery Paradox

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     THE DISCOVERY PARADOX                               │
│                                                                         │
│  Most teams spend 90% of their time building and 10% discovering.      │
│  They should spend 40% discovering and 60% building.                   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  💡 DISCOVERY IS CHEAP                                          │   │
│  │  ─────────────────────                                         │   │
│  │  It costs little to change your mind during discovery.         │   │
│  │                                                                 │   │
│  │  💸 BUILDING IS EXPENSIVE                                      │   │
│  │  ──────────────────────                                       │   │
│  │  It costs a lot to change your mind during development.       │   │
│  │                                                                 │   │
│  │  💀 LAUNCHING IS CATASTROPHIC                                   │   │
│  │  ──────────────────────────                                   │   │
│  │  It costs everything to change your mind after launch.        │   │
│  │                                                                 │   │
│  │  THE COST OF BEING WRONG:                                       │   │
│  │  ────────────────────────────────────────────────────────────  │   │
│  │  Discovery: $1,000                                            │   │
│  │  Development: $100,000                                        │   │
│  │  Launch: $1,000,000                                           │   │
│  └─────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────┘
```

### The Discovery Trap

Most teams fall into the Discovery Trap:

> *"We already know what our users need. Let's just build it."*

**The Reality:** You don't know. Your assumptions are probably wrong. And building before discovering is the #1 reason products fail.

## 3. The Discovery Toolkit

### 4 Essential Research Methods

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    4 DISCOVERY RESEARCH METHODS                         │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  METHOD 1: USER INTERVIEWS                                      │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  • Best for: Understanding user problems, motivations, context │   │
│  │  • How: 1-on-1 conversations (30-60 min)                       │   │
│  │  • Key: Ask "why," don't lead, listen                         │   │
│  │  • Output: Qualitative insights, quotes, themes                │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  METHOD 2: SURVEYS                                              │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  • Best for: Validating patterns, gathering quantitative data │   │
│  │  • How: Online surveys (5-15 min)                              │   │
│  │  • Key: Ask specific, measurable questions                    │   │
│  │  • Output: Quantitative data, trends                          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  METHOD 3: USER OBSERVATION                                     │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  • Best for: Understanding actual behavior vs. reported        │   │
│  │  • How: Watch users use your product (or a competitor's)      │   │
│  │  • Key: Don't interrupt, note friction points                │   │
│  │  • Output: Behavioral insights, friction points               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  METHOD 4: COMPETITIVE ANALYSIS                                │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  • Best for: Understanding the market and gaps                │   │
│  │  • How: Use competitors' products, read reviews               │   │
│  │  • Key: Identify what users like and don't like               │   │
│  │  • Output: Feature gaps, differentiators                      │   │
│  └─────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────┘
```

### When to Use Each Method

| Method | Best For | When to Use |
|--------|----------|-------------|
| **Interviews** | Deep understanding, "why" questions | Early in discovery |
| **Surveys** | Validating patterns, scale | After interviews |
| **Observation** | Actual behavior | Throughout discovery |
| **Competitive** | Market gaps, positioning | Early in strategy |

## 4. The Interview Masterclass

### How to Talk to Users (Without Leading Them)

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     THE INTERVIEW MASTERCLASS                            │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  RULE 1: ASK ABOUT THE PAST, NOT THE FUTURE                   │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  ❌ Bad: "Would you use a budgeting feature?"                 │   │
│  │  ✅ Good: "How do you currently track your spending?"         │   │
│  │                                                                 │   │
│  │  WHY: People are bad at predicting their future behavior.      │   │
│  │        They're good at describing their past behavior.        │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  RULE 2: ASK OPEN QUESTIONS, NOT CLOSED QUESTIONS              │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  ❌ Bad: "Do you find Ledgerly easy to use?"                  │   │
│  │  ✅ Good: "Walk me through the last time you used Ledgerly."  │   │
│  │                                                                 │   │
│  │  WHY: Open questions uncover stories. Closed questions get     │   │
│  │        yes/no answers.                                         │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  RULE 3: FOCUS ON PROBLEMS, NOT SOLUTIONS                      │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  ❌ Bad: "What features would you want?"                       │   │
│  │  ✅ Good: "What frustrates you about managing your money?"    │   │
│  │                                                                 │   │
│  │  WHY: Users are good at describing problems, bad at           │   │
│  │        designing solutions.                                    │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  RULE 4: DIG DEEPER WITH "WHY"                                 │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  User: "I stopped using the app."                              │   │
│  │  You: "Why was that?"                                          │   │
│  │  User: "It wasn't helpful."                                   │   │
│  │  You: "What do you mean by 'not helpful'?"                    │   │
│  │  User: "It showed me my spending but didn't tell me what to  │   │
│  │        do."                                                    │   │
│  │                                                                 │   │
│  │  WHY: The first answer is never the real answer. Keep        │   │
│  │        digging.                                                │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  RULE 5: LISTEN MORE, TALK LESS                                │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  • You: 20% of the time                                       │   │
│  │  • User: 80% of the time                                      │   │
│  │                                                                 │   │
│  │  WHY: You learn when you listen. You validate when you talk.  │   │
│  │        Listen first, validate later.                          │   │
│  └─────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────┘
```

### The Interview Script Template

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     INTERVIEW SCRIPT TEMPLATE                           │
│                                                                         │
│  INTRODUCTION (2 min)                                                  │
│  ────────────────────                                                  │
│  "Hi, thanks for taking the time to talk. I'm [Name], the PM for      │
│  [Product]. I'm trying to understand how people manage their          │
│  [domain]. There are no wrong answers—just your honest experience."   │
│                                                                         │
│  BACKGROUND (3 min)                                                    │
│  ───────────────────                                                   │
│  "Tell me a bit about yourself and your [domain]."                    │
│  Probe: "How do you currently [accomplish the job]?"                  │
│                                                                         │
│  THE EXPERIENCE (5 min)                                                │
│  ────────────────────                                                  │
│  "Walk me through the last time you [did the thing]."                 │
│  Probe: "What was easy? What was frustrating?"                       │
│                                                                         │
│  CHALLENGES & FRICTION (5 min)                                        │
│  ─────────────────────────                                             │
│  "What's the most frustrating thing about [the domain]?"              │
│  Probe: "Tell me more about that."                                    │
│                                                                         │
│  CLOSING (2 min)                                                       │
│  ─────────────                                                        │
│  "Is there anything else you'd like to share?"                       │
│  "Thanks so much for your time—this is incredibly helpful."          │
└─────────────────────────────────────────────────────────────────────────┘
```

## 5. The Synthesis Toolkit

### Affinity Mapping

**What It Is:** A visual tool for organizing qualitative research data into themes.

**How to Do It:**
1. Write each insight/quote on a sticky note
2. Group similar notes together
3. Label each group with a theme
4. Identify patterns and insights

**Example:**

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     AFFINITY MAP EXAMPLE                                │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  THEME: Onboarding is too hard                                 │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  "I didn't know which bank to select."                        │   │
│  │  "I tried to connect my bank but it said it couldn't."       │   │
│  │  "I don't remember my banking password."                      │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  THEME: Missing budgeting features                             │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  "I could see what I spent, but not what I could spend."      │   │
│  │  "I want to know if I'm saving enough."                       │   │
│  │  "I use a separate spreadsheet for budgeting."                │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  THEME: No motivation to return                                │   │
│  │  ───────────────────────────────────────────────────────────── │   │
│  │  "I opened it and it said the same thing as yesterday."       │   │
│  │  "I don't get notifications about anything useful."           │   │
│  │  "I don't see how it helps me improve."                        │   │
│  └─────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────┘
```

### Personas

**What They Are:** Fictional representations of user segments based on research.

**Key Components:**
- Demographics (age, location, occupation)
- Goals and motivations
- Frustrations and pain points
- Behavior patterns
- Needs and expectations

**Example Persona:**

```
Sarah - The Budget Novice
─────────────────────────

Demographics:
• Age: 26
• Occupation: Marketing Coordinator
• Location: San Francisco, CA
• Income: $65,000/year

Goals & Motivations:
• "I want to understand where my money is going."
• "I want to save enough for a vacation next year."
• "I don't want to feel guilty about spending."

Frustrations:
• "I tried budgeting apps but they're too complicated."
• "I don't understand financial jargon."
• "I feel anxious when I think about money."

Behavior Patterns:
• Checks apps once a week
• Uses basic features only
• Never set up a budget

Needs:
• Simple guidance
• Clear next steps
• Positive reinforcement
```

### Jobs-to-Be-Done (JTBD)

**What It Is:** A framework for understanding why users "hire" your product.

**The 3 Job Components:**
1. **Functional Job:** What the user wants to accomplish
2. **Emotional Job:** How the user wants to feel
3. **Social Job:** How the user wants to be perceived

**Example:**

| Job Type | Example for Ledgerly |
|----------|----------------------|
| Functional | "Help me understand where my money is going." |
| Emotional | "Help me feel in control of my finances." |
| Social | "Help me be seen as financially responsible." |

**JTBD Statement:**
> "When I feel overwhelmed by my finances, I want to easily track my spending so I can feel in control of my money."

## 6. The 5 Discovery Pitfalls

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     5 DISCOVERY PITFALLS                                │
│                                                                         │
│  PITFALL 1: LEADING QUESTIONS                                          │
│  ──────────────────────────                                            │
│  ❌ Mistake: "Would you use a budgeting feature?"                     │
│  ✅ Fix: "How do you currently track your spending?"                  │
│                                                                         │
│  PITFALL 2: ASKING ABOUT THE FUTURE                                   │
│  ────────────────────────────                                         │
│  ❌ Mistake: "Would you pay for this feature?"                       │
│  ✅ Fix: "What have you paid for in the past?"                        │
│                                                                         │
│  PITFALL 3: TALKING MORE THAN LISTENING                               │
│  ───────────────────────────────                                      │
│  ❌ Mistake: Talking 50%+ of the time                                │
│  ✅ Fix: Aim for 20% talking, 80% listening                           │
│                                                                         │
│  PITFALL 4: STOPPING AT THE FIRST "WHY"                              │
│  ──────────────────────────────                                       │
│  ❌ Mistake: Accepting the first answer                              │
│  ✅ Fix: Ask "why" 3 times to get to the root                        │
│                                                                         │
│  PITFALL 5: VALIDATING, NOT DISCOVERING                              │
│  ────────────────────────────────────                                 │
│  ❌ Mistake: "I think users want X. Let me confirm."                 │
│  ✅ Fix: "What do users actually need? Let me find out."             │
└─────────────────────────────────────────────────────────────────────────┘
```

## 7. Your Discovery Mantra

### The One Question That Unlocks Everything

When you're stuck, when you don't know where to start, when you're about to build something—ask yourself:

> *"What is the user trying to accomplish, and what's preventing them from doing it?"*

### Why This Works

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     THE DISCOVERY MANTRA                                │
│                                                                         │
│  "WHAT IS THE USER TRYING TO ACCOMPLISH..."                           │
│  ───────────────────────────────────────────────────────────────       │
│  • Focuses on the user, not the product                              │
│  • Identifies the "job" the user needs to do                        │
│  • Prevents you from jumping to solutions                            │
│                                                                         │
│  "...AND WHAT'S PREVENTING THEM FROM DOING IT?"                     │
│  ───────────────────────────────────────────────────────────────       │
│  • Identifies friction and pain points                              │
│  • Reveals where you can help                                        │
│  • Defines the problem you're solving                                │
│                                                                         │
│  Use this mantra when:                                                │
│  • You're about to build a feature                                   │
│  • You're conducting user interviews                                 │
│  • You're analyzing research data                                    │
│  • You're defining your product strategy                            │
└─────────────────────────────────────────────────────────────────────────┘
```

### Applying the Mantra to Ledgerly

**What the user is trying to accomplish:**
"I want to feel in control of my finances and know where my money is going."

**What's preventing them:**
- I don't know how to get started
- The app doesn't guide me
- I don't see progress or improvement
- I forget to check the app

**The Problem Statement (derived from the mantra):**
"Users don't stay engaged because Ledgerly doesn't help them set goals, track progress, or build habits."
