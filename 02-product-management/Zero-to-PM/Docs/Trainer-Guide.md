# Trainer Guide: The Zero-to-One Product Manager

## A Comprehensive Facilitator's Manual for Teaching the Series

---

## How to Use This Trainer Guide

This guide is designed for instructors, mentors, workshop facilitators, and bootcamp leads who are teaching the "Zero-to-One Product Manager" series. It provides:

1. **Facilitation Best Practices** - How to lead engaging sessions
2. **Part-by-Part Lesson Plans** - Detailed session structures for each part
3. **Activity Guides** - Step-by-step instructions for hands-on exercises
4. **Discussion Prompts** - Questions to spark engagement and deeper thinking
5. **Assessment Tools** - Rubrics and evaluation frameworks
6. **Customization Options** - Adapting content for different audiences

## PART 1: The PM Role Demystified (60-75 minutes)

### Learning Objectives
- Participants understand what PMs actually do
- Participants can articulate the difference between PM, Project Manager, and Program Manager
- Participants write their PM philosophy

### Agenda

| Time | Activity | Description |
|------|----------|-------------|
| 5 min | Recap & Context | Connect to Part 0 |
| 15 min | Core Concept | What PMs do (translation analogy) |
| 10 min | PM vs. Other Roles | Compare and contrast roles |
| 20 min | Hands-On: PM Philosophy | Write personal PM philosophy |
| 15 min | Discussion & Sharing | Participants share philosophies |
| 5 min | Wrap-Up | Key takeaways |

### Core Concept Script

**The Translation Analogy:**

"Imagine you're at a table with three people:
- A user who speaks only 'User' (needs, problems, frustrations)
- An engineer who speaks only 'Tech' (code, databases, APIs)
- A business leader who speaks only 'Business' (revenue, costs, strategy)

You're the translator. You understand all three languages, and you help them understand each other.

That's your job as a PM."

### Discussion Activity: PM vs. Other Roles

**Instructions for Participants:**
1. Split into groups of 3-4
2. Each group is assigned a role: PM, Project Manager, or Program Manager
3. Groups describe their role in 3 bullet points
4. Present to the class

**Key Comparisons:**

| Role | Focus |
|------|-------|
| PM | What to build and why |
| Project Manager | How to deliver on time |
| Program Manager | Coordinating multiple projects |

### Hands-On: PM Philosophy

**Exercise Instructions:**

"Take 15 minutes to write your PM philosophy. Answer these questions:
1. Why do you want to be a PM?
2. What are your superpowers?
3. How do you make decisions?
4. What kind of PM do you want to be?

Then, write a one-paragraph statement."

**Example to Share:**

> "My philosophy as a product manager centers on user empathy and data-informed decision-making. I believe that great products emerge from deeply understanding user problems and validating solutions with evidence. I prioritize clarity in communication, transparency in trade-offs, and collaboration across disciplines."

### Common Questions

- "Do I need to be technical to be a PM?"
  - *Answer:* No, but you should be curious about technology.
- "What's the hardest part of being a PM?"
  - *Answer:* Making decisions without perfect information.

## PART 2: User Research & Discovery (75-90 minutes)

### Learning Objectives
- Participants understand the discovery process
- Participants can write research questions
- Participants can create personas and affinity maps

### Agenda

| Time | Activity | Description |
|------|----------|-------------|
| 5 min | Recap & Context | Connect to Part 1 |
| 15 min | Core Concept | The discovery process |
| 10 min | Research Questions | How to write good research questions |
| 20 min | Hands-On: Interview Script | Write an interview script |
| 15 min | Hands-On: Affinity Map | Group quotes into themes |
| 10 min | Discussion | Share findings and insights |
| 5 min | Wrap-Up | Key takeaways |

### Core Concept Script

**The Discovery Process:**

"Discovery has four phases:
1. **Plan:** Define goals, write questions, recruit participants
2. **Conduct:** Interview users, observe behavior
3. **Synthesize:** Find patterns, create personas, identify insights
4. **Validate:** Test assumptions with more research

Discovery is cheap; building is expensive. Discover before you build."

### Activity: Write Research Questions

**Exercise Instructions:**

"Using the Ledgerly scenario, write 3-4 research questions for these goals:
1. Understand why users sign up
2. Understand why users churn
3. Understand what keeps users engaged

Remember: Ask about the past, not the future. Ask open questions. Focus on problems, not solutions."

**Sample Answers to Share:**

**Goal 1:** "What was happening in your life when you signed up for Ledgerly?"
**Goal 2:** "Walk me through the last time you used Ledgerly."
**Goal 3:** "What's the most valuable thing Ledgerly does for you?"

### Hands-On: Affinity Map

**Supplies Needed:**
- Sticky notes (physical or digital)
- Whiteboard or virtual whiteboard

**Exercise Instructions:**

"Here are 10 quotes from Ledgerly user interviews. Group them into 3 themes."

**Quotes to Provide:**
1. "I didn't know which bank to select."
2. "I could see what I spent, but not what I could spend."
3. "I opened it and it said the same thing as yesterday."
4. "I tried to connect my bank but it said it couldn't."
5. "I want to know if I'm saving enough."
6. "I don't get notifications about anything useful."
7. "I don't remember my banking password."
8. "I use a separate spreadsheet for budgeting."
9. "I don't see how it helps me improve."
10. "I don't want to feel guilty about spending."

**Expected Themes:**
1. Onboarding is too hard (Quotes 1, 4, 7)
2. Missing budgeting features (Quotes 2, 5, 8)
3. No motivation to return (Quotes 3, 6, 9)
4. Emotional barriers (Quote 10)

### Discussion Prompts

- "What surprised you about these user quotes?"
- "What problem would you prioritize solving first?"
- "What would you ask users in a follow-up interview?"

## PART 3: Jobs-to-Be-Done Framework (60-75 minutes)

### Learning Objectives
- Participants understand the JTBD framework
- Participants can create a JTBD canvas
- Participants can write a JTBD statement

### Agenda

| Time | Activity | Description |
|------|----------|-------------|
| 5 min | Recap & Context | Connect to Part 2 |
| 15 min | Core Concept | What is JTBD? |
| 15 min | JTBD Canvas | Walk through the canvas |
| 15 min | Hands-On: JTBD Statement | Write a JTBD statement |
| 10 min | Discussion | Share and discuss |
| 5 min | Wrap-Up | Key takeaways |

### Core Concept Script

**The JTBD Metaphor:**

"Imagine a customer buying a drill at a hardware store.
- Traditional thinking: 'This customer wants a 3/4-inch drill bit.'
- JTBD thinking: 'This customer wants a 3/4-inch hole.'

The drill bit is the solution. The hole is the job.

When you understand the job, you can explore different solutions. Maybe you don't need a drill bit at all. Maybe you need to hang a picture, and there are better ways to do that."

**The Three Job Components:**
1. Functional: What they want to accomplish
2. Emotional: How they want to feel
3. Social: How they want to be perceived

### Hands-On: JTBD Canvas

**Exercise Instructions:**

"Complete the JTBD Canvas for Ledgerly."

**Canvas Template:**

| Section | Your Answer |
|---------|-------------|
| Functional Job | |
| Emotional Job | |
| Social Job | |
| Current Solution | |
| Friction Points | |
| Success Metrics | |

**Sample Answers:**

| Section | Sample Answer |
|---------|---------------|
| Functional Job | "Help me understand where my money is going." |
| Emotional Job | "Help me feel in control of my finances." |
| Social Job | "Help me be seen as financially responsible." |
| Current Solution | "Spreadsheets, banking apps, doing nothing." |
| Friction Points | "Manual data entry, no guidance, technical issues." |
| Success Metrics | "See net worth increase, hit savings goals, reduce anxiety." |

### Hands-On: JTBD Statement

**Exercise Instructions:**

"Write a JTBD statement using this template:
> When [circumstance], I want to [functional job] so I can [emotional/social outcome]."

**Sample:**
> "When I feel overwhelmed by my finances, I want to easily track my spending so I can feel in control of my money."

### Discussion Prompts

- "How is JTBD different from asking users what features they want?"
- "What's an example of a product that does a job well?"
- "What's a product that does a job poorly?"

### Core Concept Script

**The Strategy Pyramid:**

"Strategy has four levels:
1. **Vision:** The ultimate destination (years)
2. **Strategy:** The path to get there (quarters)

## PART 6: Prioritization Frameworks (60-75 minutes)

### Learning Objectives
- Participants can use RICE scoring
- Participants can use the Kano model
- Participants can create a prioritized backlog

### Agenda

| Time | Activity | Description |
|------|----------|-------------|
| 5 min | Recap & Context | Connect to Part 5 |
| 15 min | Core Concept | RICE and Kano |
| 15 min | Hands-On: RICE | Calculate RICE scores |
| 15 min | Hands-On: Kano | Categorize features |
| 10 min | Discussion | Share decisions |
| 5 min | Wrap-Up | Key takeaways |

### Core Concept Script

**RICE Scoring:**
RICE = (Reach × Impact × Confidence) ÷ Effort

- Reach: Users affected
- Impact: 3=Massive, 2=High, 1=Medium, 0.5=Low
- Confidence: 100%=High, 80%=Medium, 50%=Low
- Effort: Person-months

**Kano Model:**
- Basic: Table stakes; absence causes dissatisfaction
- Performance: Linear satisfaction; more is better
- Excitement: Delighters; unexpected value
- Indifferent: Doesn't affect satisfaction

### Hands-On: RICE Scoring

**Exercise Instructions:**

"Score these features using RICE."

**Features to Score:**

| Feature | Reach | Impact | Confidence | Effort | RICE Score |
|---------|-------|--------|------------|--------|------------|
| Goal Setting | 50,000 | 3 | 85% | 2 | |
| Improved Onboarding | 20,000 | 3 | 90% | 1 | |
| Weekly Summaries | 40,000 | 2 | 75% | 1 | |
| Budget Creation | 40,000 | 2 | 80% | 2 | |
| Actionable Insights | 50,000 | 2 | 70% | 2 | |

**Calculations:**
- Goal Setting: (50,000 × 3 × 0.85) ÷ 2 = 63,750
- Improved Onboarding: (20,000 × 3 × 0.90) ÷ 1 = 54,000
- Weekly Summaries: (40,000 × 2 × 0.75) ÷ 1 = 60,000
- Budget Creation: (40,000 × 2 × 0.80) ÷ 2 = 32,000
- Actionable Insights: (50,000 × 2 × 0.70) ÷ 2 = 35,000

**Ranking:**
1. Goal Setting (63,750)
2. Weekly Summaries (60,000)
3. Improved Onboarding (54,000)
4. Actionable Insights (35,000)
5. Budget Creation (32,000)

## PART 7: Writing PRDs (75-90 minutes)

### Learning Objectives
- Participants understand PRD structure
- Participants can write user stories
- Participants can write acceptance criteria

### Agenda

| Time | Activity | Description |
|------|----------|-------------|
| 5 min | Recap & Context | Connect to Part 6 |
| 15 min | Core Concept | PRD structure and user stories |
| 20 min | Hands-On: User Stories | Write user stories |
| 20 min | Hands-On: Acceptance Criteria | Write acceptance criteria |
| 15 min | Discussion | Share and review |
| 5 min | Wrap-Up | Key takeaways |

### Core Concept Script

**PRD Structure:**
1. Executive Summary: What and why
2. Problem Statement: What problem
3. User Stories: As a/I want/So that
4. Success Metrics: How to measure
5. Detailed Requirements: Functional, non-functional
6. Out of Scope: What we're NOT building

**User Story Format:**
> "As a [type of user], I want [some goal], So that [some reason]."

**Acceptance Criteria:**
- Specific, testable, unambiguous
- Example: "Goal appears on dashboard within 5 seconds"

### Hands-On: User Stories

**Exercise Instructions:**

"Write 5 user stories for the Goal Setting feature."

**Sample User Stories:**
1. "As a user who wants to save money, I want to create a savings goal with a target amount and deadline, so that I have a clear target to work toward."
2. "As a user who wants to manage my spending, I want to create a spending goal for a specific category, so that I can stay within my budget."
3. "As a user with debt, I want to create a debt reduction goal, so that I can become debt-free."
4. "As a user tracking goals, I want to edit my goal parameters, so that my goals stay relevant."
5. "As a user who no longer needs a goal, I want to delete it from my dashboard, so that my dashboard stays clean."

### Hands-On: Acceptance Criteria

**Exercise Instructions:**

"Write acceptance criteria for one of your user stories."

**Sample: Story 1 - Create a Savings Goal**

**Acceptance Criteria:**
- [ ] User can access "Set a Goal" from dashboard
- [ ] User can select "Savings Goal" from goal types
- [ ] User can enter target amount (minimum $1)
- [ ] User can enter target date (must be future date)
- [ ] User can save goal after entering required fields
- [ ] Goal appears on dashboard with progress bar at 0%
- [ ] User receives confirmation message on successful save

**Edge Cases:**
- Invalid amount (0 or negative): show error message
- Past target date: show error message
- Missing required fields: show error message
- User cancels goal creation: no goal is saved

### Discussion Prompts

- "What's the most important section of a PRD?"
- "How do user stories help product teams?"
- "Why is 'Out of Scope' important?"

**The Growth Pyramid:**

**The Iteration Cycle:**
