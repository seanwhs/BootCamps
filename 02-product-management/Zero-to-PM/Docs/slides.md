```

                           THE PM DEFINITION

                        Product Management is the practice
                        of identifying user problems that
                        are worth solving, defining solutions
                        that deliver business value, and
                        working with cross-functional teams
                        to ship those solutions, then
                        measuring and iterating to
                        continuously improve.

                        ───

                        PMs are translators between
                        Business, Users, and Technology.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

```
                        │  NOT: "Would you use this?"       │
                        └─────────────────────────────────────┘

                        ┌─────────────────────────────────────┐
                        │  RULE 2: ASK OPEN QUESTIONS       │
                        │  "Walk me through..."             │
                        │  NOT: "Do you like..."            │
                        └─────────────────────────────────────┘

                        ┌─────────────────────────────────────┐
                        │  RULE 3: FOCUS ON PROBLEMS        │

                        ┌─────────────────────────────────────┐

                        │  Ask "why" 3 times                │
                        └─────────────────────────────────────┘

                        ┌─────────────────────────────────────┐
                        │  RULE 5: LISTEN 80%, TALK 20%    │
                        └─────────────────────────────────────┘
```

### SLIDE 80: RICE Scoring

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

                           RICE SCORING

                        ┌─────────────────────────────────────┐
                        │  RICE = (Reach × Impact ×          │
                        │         Confidence) ÷ Effort       │
                        └─────────────────────────────────────┘

                        ┌─────────────────────────────────────┐
                        │  REACH                             │
                        │  Number of users affected          │
                        │  Example: 50,000 users             │
                        └─────────────────────────────────────┘

                        ┌─────────────────────────────────────┐
                        │  IMPACT                            │
                        │  3 = Massive  2 = High             │
                        │  1 = Medium   0.5 = Low            │
                        └─────────────────────────────────────┘

                        ┌─────────────────────────────────────┐
                        │  CONFIDENCE                        │
                        │  100% = High  80% = Medium         │
                        │  50% = Low                         │
                        └─────────────────────────────────────┘

                        ┌─────────────────────────────────────┐
                        │  EFFORT                            │
                        │  Person-months or story points     │
                        │  Example: 2 person-months          │
                        └─────────────────────────────────────┘

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### SLIDE 81: RICE Example

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

                           RICE EXAMPLE

                        ┌─────────────────────────────────────┐
                        │  FEATURE: GOAL SETTING              │
                        │                                    │
                        │  Reach: 50,000                     │
                        │  Impact: 3 (Massive)               │
                        │  Confidence: 85%                   │
                        │  Effort: 2 person-months           │
                        │                                    │
                        │  RICE = (50,000 × 3 × 0.85) ÷ 2   │
                        │       = 127,500 ÷ 2                │
                        │       = 63,750                    │
                        └─────────────────────────────────────┘

                        ┌─────────────────────────────────────┐
                        │  FEATURE: INVESTMENT TRACKING       │
                        │                                    │
                        │  Reach: 15,000                     │
                        │  Impact: 1 (Medium)                │
                        │  Confidence: 60%                   │
                        │  Effort: 3 person-months           │
                        │                                    │
                        │  RICE = (15,000 × 1 × 0.60) ÷ 3   │
                        │       = 9,000 ÷ 3                  │
                        │       = 3,000                      │
                        └─────────────────────────────────────┘

                        Goal Setting: 63,750
                        Investment Tracking: 3,000
                        → Goal Setting is 21x higher priority

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### SLIDE 92: What Is a PRD?

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

                           WHAT IS A PRD?

                        PRD = PRODUCT REQUIREMENTS DOCUMENT

                        ─────────────────────────────────────

                        A PRD answers one question:

                        "What exactly are we building,
                        and how will we know it's done?"

                        ─────────────────────────────────────

                        A PRD IS NOT:
                        • A technical specification
                        • A design mockup
                        • A marketing brief
                        • A project plan

                        A PRD IS:
                        • The bridge between strategy
                          and execution
                        • A single source of truth
                        • A conversation starter

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### SLIDE 93: PRD Structure

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

                           PRD STRUCTURE

                        1. EXECUTIVE SUMMARY
                           What are we building and why?

                        2. PROBLEM STATEMENT
                           What problem are we solving?

                        3. USER STORIES
                           As a [user], I want [goal], So
                           that [reason]

                        4. SUCCESS METRICS
                           How will we know it worked?

                        5. DETAILED REQUIREMENTS
                           Functional, non-functional,
                           technical

                        6. OUT OF SCOPE
                           What are we NOT building?

                        7. APPENDIX
                           User flows, wireframes, research

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### SLIDE 96: Acceptance Criteria

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

                           ACCEPTANCE CRITERIA

                        ACCEPTANCE CRITERIA SHOULD BE:

                        • SPECIFIC
                          "Users can set a goal between
                           $1 and $1,000,000"

                        • TESTABLE
                          "Goal appears on dashboard within
                           5 seconds"

                        • UNAMBIGUOUS
                          "Progress updates automatically
                           when transactions occur"

                        ─────────────────────────────────────

                        ACCEPTANCE CRITERIA FORMAT:

                        GIVEN [context]
                        WHEN [action]
                        THEN [outcome]

                        ─────────────────────────────────────

                        EXAMPLE:
                        GIVEN the user has connected a bank
                        WHEN the user sets a goal
                        THEN the goal appears on the dashboard

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

```
                        │  • Only include the happy path    │

                        │  • Surprise stakeholders          │
```

### SLIDE 136: The Growth Equation

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

                           THE GROWTH EQUATION

                        GROWTH =
                        ACQUISITION × ACTIVATION ×
                        RETENTION × REFERRAL × REVENUE

                        ─────────────────────────────────────

                        KEY INSIGHT:
                        If any factor is zero, growth is zero.

                        ─────────────────────────────────────

                        EXAMPLE:
                        If acquisition is high but retention
                        is low, you're acquiring users who
                        churn.

                        → Fix retention before scaling
                          acquisition.

                        ─────────────────────────────────────

                        LEDGERLY'S GROWTH PRIORITIES:
                        1. Retention (20% → 40%)
                        2. Activation (60% → 75%)
                        3. Goal Adoption (32% → 50%)
                        4. Acquisition (Scale after retention)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
