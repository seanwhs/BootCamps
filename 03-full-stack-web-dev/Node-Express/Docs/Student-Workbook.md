# How to Use This Workbook

## Welcome to Your Learning Companion!

This workbook is designed to accompany the **Node.js + Express Tutorial Series: From Zero to Building Real Web Apps**. It's not just a collection of exercises — it's a complete learning system that will help you:

1. **Prepare** for each lesson with pre-reading questions
2. **Engage** with key concepts through structured exercises
3. **Practice** with hands-on coding challenges
4. **Review** with self-assessment quizzes
5. **Reflect** on what you've learned
6. **Track** your progress through the series

## Workbook Structure

Each part of the tutorial has a dedicated section in this workbook containing:

| Section | Purpose | When to Complete |
|---------|---------|------------------|
| **Pre-Reading Questions** | Activate prior knowledge and set learning goals | Before reading the tutorial |
| **Key Concepts** | Summarize and reinforce main ideas | During or after reading |
| **Code Along Exercises** | Hands-on practice with guided steps | After reading, before moving on |
| **Practice Problems** | Apply what you've learned independently | After completing code-along |
| **Vocabulary Builder** | Build technical vocabulary | Throughout the lesson |
| **Reflection Questions** | Deepen understanding through writing | After completing the lesson |
| **Self-Assessment Quiz** | Check your understanding | Before moving to next part |

## How to Use This Workbook Effectively

### Before Each Lesson
1. **Read the pre-reading questions** to activate your prior knowledge

### Common HTTP Status Codes

Fill in the missing status codes:

| Code | Meaning | When to Use |
|------|---------|-------------|
| 200 | _______________ | Everything worked |
| 201 | _______________ | A new resource was created |
| 400 | Bad Request | The request is invalid |

| 404 | _______________ | The resource doesn't exist |
| 500 | _______________ | Something went wrong on the server |

### Node.js HTTP Module

The `http` module provides three main functions:

1. `http.createServer()` - Creates a server object
2. `http.request()` - Creates HTTP requests (client)
3. `http.get()` - Simplified GET requests

The request handler function takes two parameters:
```javascript
http.createServer((_________, _________) => {
    // Handle request
});
```

### The Request Object (req)

| Property | What It Contains |
|----------|------------------|
| `req.method` | The HTTP method (GET, POST, etc.) |
| `req.url` | The URL path with query string |
| `req.headers` | Request headers as an object |
| `req.socket.remoteAddress` | The client's IP address |

### The Response Object (res)

| Method | What It Does |
|--------|--------------|
| `res.writeHead(status, headers)` | Sets status code and headers |
| `res.setHeader(name, value)` | Sets a single header |
| `res.write(data)` | Writes part of the response body |
| `res.end(data)` | Finishes and sends the response |

## Key Concepts (Part 4)

### URL Anatomy

```
https://example.com:3000/users/123/posts?page=2&sort=recent#comments
\______/   \______/ \__/ \____/ \_/ \____/ \______________/ \______/
 protocol   domain   port  path   id   path    query string    fragment
                             segment         (optional)      (optional)
```

### Route Parameters

Route parameters are defined with a colon `:` and captured in `req.params`:

| Route | URL | `req.params` |
|-------|-----|--------------|
| `/users/:id` | `/users/123` | `{ id: '123' }` |
| `/users/:id/posts/:postId` | `/users/123/posts/456` | `{ id: '123', postId: '456' }` |
| `/users/:id?` | `/users/123` or `/users` | `{ id: '123' }` or `{}` |
| `/users/:id(\\d+)` | `/users/123` only | `{ id: '123' }` |

### Query Strings

Query strings are captured in `req.query`:

| URL | `req.query` |
|-----|-------------|
| `/users?page=2` | `{ page: '2' }` |
| `/users?page=2&limit=10` | `{ page: '2', limit: '10' }` |
| `/users?search=hello&sort=recent` | `{ search: 'hello', sort: 'recent' }` |

### HTTP Methods

| Method | Purpose | Idempotent | Safe |
|--------|---------|------------|------|
| GET | Retrieve data | Yes | Yes |
| POST | Create new data | No | No |
| PUT | Replace entire resource | Yes | No |
| PATCH | Partial update | No | No |
| DELETE | Delete data | Yes | No |

### express.Router()

`express.Router()` helps organize routes into separate modules:

```javascript
// routes/users.js
const express = require('express');
const router = express.Router();

router.get('/', (req, res) => { /* ... */ });
router.get('/:id', (req, res) => { /* ... */ });
router.post('/', (req, res) => { /* ... */ });

module.exports = router;

// app.js
const usersRouter = require('./routes/users');
app.use('/users', usersRouter);
```

## Key Concepts (Part 5)

### What Is Middleware?

Middleware is a function that executes during the **request-response cycle**, in the middle between when the request arrives and when the response is sent.

**Think of middleware like security checkpoints at an airport:**

```
You enter → Check-in (logging) → Security (authentication) → Gate (routing) → Board (response)
```

Each checkpoint:
1. Receives you (the request)
2. Can examine you (check your data)
3. Can modify you (add information)
4. Can stop you (send an error response)
5. Can pass you to the next checkpoint (call `next()`)

### Middleware Function Signature

```javascript
function middleware(req, res, next) {
    // 1. Do something with the request
    // 2. Either: Send a response (end the cycle)
    // 3. Or: Call next() to continue to the next middleware
}
```

### Types of Middleware

| Type | Example | Description |
|------|---------|-------------|
| **Application-level** | `app.use(logger)` | Runs for all requests |
| **Router-level** | `router.use(auth)` | Runs for specific routes |
| **Error-handling** | `app.use((err, req, res, next) => {})` | Catches errors |
| **Built-in** | `express.json()`, `express.static()` | Comes with Express |
| **Third-party** | `cors()`, `helmet()`, `morgan()` | Installed from npm |

### Common Built-in Middleware

| Middleware | Purpose |
|------------|---------|
| `express.json()` | Parse JSON request bodies |
| `express.urlencoded({ extended: true })` | Parse URL-encoded form data |
| `express.static('public')` | Serve static files |

### Custom Middleware Examples

```javascript
// 1. Logging middleware
app.use((req, res, next) => {
    console.log(`${req.method} ${req.url}`);
    next();
});

// 2. Authentication middleware
app.use((req, res, next) => {
    const token = req.headers.authorization;
    if (!token) {
        return res.status(401).json({ error: 'Unauthorized' });
    }
    // Verify token...
    next();
});

// 3. Error handling middleware
app.use((err, req, res, next) => {
    console.error(err);
    res.status(500).json({ error: 'Something went wrong' });
});
```

### Types of Storage

| Type | Description | Pros | Cons |
|------|-------------|------|------|
| In-memory | Data stored in RAM | Fast | Lost on restart |
| File-based | Data stored in files | Simple, persistent | Limited scalability |
| Database | Data stored in DBMS | Scalable, robust | Complex, requires setup |

### CRUD Operations

| Operation | HTTP Method | SQL Equivalent | Description |
|-----------|-------------|----------------|-------------|
| Create | POST | INSERT | Add new data |
| Read | GET | SELECT | Retrieve data |
| Update | PUT/PATCH | UPDATE | Modify data |
| Delete | DELETE | DELETE | Remove data |

### File-Based Storage with JSON

```javascript
// Reading from JSON file
const fs = require('fs').promises;

async function readData() {
    try {
        const data = await fs.readFile('data.json', 'utf-8');
        return JSON.parse(data);
    } catch (error) {
        if (error.code === 'ENOENT') {
            return [];
        }
        throw error;
    }
}

// Writing to JSON file
async function writeData(data) {
    const jsonString = JSON.stringify(data, null, 2);
    await fs.writeFile('data.json', jsonString, 'utf-8');
}
```

```javascript
class AppError extends Error {
    constructor(message, statusCode = 500) {
        super(message);

    }

class ValidationError extends AppError {
    constructor(message, errors = []) {

        this.errors = errors;
```

### Error Handling Middleware

```javascript
// Error handling middleware (must be last)
app.use((err, req, res, next) => {
    console.error('Error:', err);
    
    const status = err.statusCode || 500;
    const message = err.message || 'Internal server error';
    
    res.status(status).json({
        success: false,
        error: {
            message,
            ...(process.env.NODE_ENV === 'development' && {
                stack: err.stack
            })
        }
    });
});
```

```javascript
const Joi = require('joi');

const userSchema = Joi.object({
    name: Joi.string().min(2).max(50).required(),
    email: Joi.string().email().required(),
    password: Joi.string().min(8).required(),

const validate = (schema) => {
    return (req, res, next) => {
        const { error, value } = schema.validate(req.body, {
            abortEarly: false,
            stripUnknown: true,
        });
        
        if (error) {
            const errors = error.details.map(d => ({
                field: d.path[0],
                message: d.message
            }));
            
            return res.status(400).json({
                success: false,
                errors
            });
        }
        
        req.body = value;
        next();
    };
};
```

# Appendix: Glossary

## A
**API (Application Programming Interface)** - A set of rules and protocols for building and interacting with software applications.

**Async/Await** - JavaScript syntax for working with promises in a more synchronous-looking way.

**Authentication** - The process of verifying the identity of a user or system.

**Authorization** - The process of determining what permissions an authenticated user has.

## B
**Backend** - The server-side part of a web application that handles data processing, storage, and business logic.

**bcrypt** - A library for hashing passwords securely.

**Body** - The data payload of an HTTP request or response.

## C
**Client** - A device or program that requests services from a server.

**CORS (Cross-Origin Resource Sharing)** - A security mechanism that allows web pages from one domain to access resources from another domain.

**Controller** - A component that handles HTTP requests and coordinates between routes and models.

**CRUD (Create, Read, Update, Delete)** - The four basic operations for data management.

## D
**Database** - A structured collection of data organized for efficient retrieval and storage.

**Deployment** - The process of making an application available for use.

## E

**Error Handling** - The process of catching and responding to errors gracefully.

## G
