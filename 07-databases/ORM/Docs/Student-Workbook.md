# Appendix J: Student Workbook – Hands‑On Exercises and Checkpoints

## How to Use This Workbook

This workbook is your companion to the **Drizzle vs. Prisma Masterclass**. It contains hands‑on exercises, checkpoint challenges, and self‑assessment checklists for each part of the series.

- **Before watching/reading a part:** Look at the objectives and warm‑up questions.
- **During the part:** Follow along with the coding exercises.
- **After the part:** Complete the checkpoints and reflection questions.

Use the **answer keys** provided in the test bank for self‑checking, but try to solve problems on your own first.

## Part 0: Introduction – Getting Ready

### Objectives
- Set up your development environment.
- Understand the architecture and scope of the series.

### Warm‑Up
1. What is an ORM and why do we use one in a TypeScript application?
2. List three differences between a traditional ORM and a modern TypeScript‑first ORM.

### Hands‑On Exercises

#### Exercise 0.1: Verify Your Setup
Run the following commands and note the outputs:
```bash
node --version
pnpm --version
docker --version
git --version
```
If any are missing, install them before proceeding.

#### Exercise 0.2: Create the Project Repository
```bash
mkdir taskflow-pro
cd taskflow-pro
git init
```

Create a basic `package.json` and `README.md`. Push to a GitHub repository (optional but recommended).

#### Exercise 0.3: Start PostgreSQL via Docker
```bash
docker run --name taskflow-postgres \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=taskflow \
  -p 5432:5432 \
  -d postgres:16-alpine
```
Verify it’s running:
```bash
docker ps
```

### Checkpoint
- [ ] Node.js 20+ installed.
- [ ] pnpm installed.
- [ ] Docker and Docker Compose installed.
- [ ] PostgreSQL container running.

### Reflection Question
What excites you most about learning two ORMs in parallel?

## Part 1: ORM Philosophy and Architecture

### Objectives
- Explain the differences between Prisma and Drizzle.
- Set up both ORMs in a monorepo.

### Warm‑Up
1. What does "schema‑first" mean in Prisma?
2. What does "code‑first" mean in Drizzle?

### Hands‑On Exercises

#### Exercise 1.1: Create the Monorepo
Follow the steps in Part 1 to create a pnpm workspace with a database package. Your folder structure should look like:
```
taskflow-pro/
├── packages/
│   └── database/
│       ├── src/
│       │   ├── prisma/
│       │   └── drizzle/
│       ├── package.json
│       └── tsconfig.json
├── pnpm-workspace.yaml
└── package.json
```

#### Exercise 1.2: Install Dependencies
In the `database` package, install both ORMs and their dependencies. Run:
```bash
pnpm add prisma @prisma/client drizzle-orm pg
pnpm add -D drizzle-kit @types/pg
```

#### Exercise 1.3: Define a Minimal Schema (User and Post)
**Prisma schema:** Create `prisma/schema.prisma` with a `User` and `Post` model (one‑to‑many). **Drizzle schema:** Create `drizzle/schema.ts` with equivalent tables using `pgTable` and relations.

#### Exercise 1.4: Run Migrations
- Prisma: `prisma migrate dev --name init`
- Drizzle: `drizzle-kit generate:pg` and then apply using the migration runner (or `push` in development).

#### Exercise 1.5: Write a Seed Script
Write a `seed.ts` that inserts at least one user and one post using both ORMs (or choose one for seeding, but know both).

### Checkpoint
- [ ] Monorepo structure is correct.
- [ ] Both Prisma and Drizzle schemas are defined.
- [ ] Migrations ran without errors.
- [ ] Seed script runs successfully.

### Troubleshooting Tips
- If Prisma migration fails, check your `DATABASE_URL` in `.env`.
- If Drizzle cannot find the schema, verify `drizzle.config.ts` points to the right file.
- If you see "relation already exists", drop the database and start fresh (development only).

### Reflection Question
Which setup felt more intuitive to you? Why?

## Part 2: Schema Design and Migrations

### Objectives
- Expand the schema to include all TaskFlow Pro tables.
- Understand advanced migration strategies.

### Warm‑Up
1. What is a composite unique constraint and when would you use it?
2. Explain the difference between `CASCADE` and `RESTRICT` on foreign key deletes.

### Hands‑On Exercises

#### Exercise 2.1: Complete the Schema
Add all the tables from the series: `projects`, `tasks`, `comments`, `attachments`, `activity_logs`, and `webhook_events`. Include appropriate relations, indexes, and enums.

#### Exercise 2.2: Generate and Apply Migrations
Generate a single migration that creates all tables. Verify the SQL generated by both ORMs and compare.

#### Exercise 2.3: Customise a Migration
For Prisma, generate a migration with `--create-only`, then add a custom index that uses `CONCURRENTLY`. For Drizzle, edit the generated SQL to add a `CHECK` constraint.

#### Exercise 2.4: Write a Data Migration
Write a script that backfills a new column (e.g., `priority_rank`) based on an existing column (e.g., `priority`) using both ORMs.

### Checkpoint
- [ ] All tables are present in both schemas.
- [ ] Migrations apply without errors.
- [ ] Custom migration SQL is understood and tested.

### Reflection Question
Which ORM gave you more control over the generated SQL? Which felt safer?

## Part 3: Querying, Performance, and Type Safety

### Objectives
- Write type‑safe CRUD operations.
- Implement advanced queries (filtering, sorting, aggregations, joins, pagination).
- Understand and run benchmarks.

### Warm‑Up
1. What is the N+1 problem and how do ORMs help avoid it?
2. When would you use a raw SQL query instead of the ORM's API?

### Hands‑On Exercises

#### Exercise 3.1: Basic CRUD
Implement functions for both ORMs that:
- Create a user with a hashed password.
- Create a project with a list of tasks.
- Update a task's status.
- Delete a comment.
- Find a user by email with their projects.

#### Exercise 3.2: Advanced Filtering
Write a query that retrieves tasks with:
- Title containing a keyword (case‑insensitive).
- Status in `['todo', 'in_progress']`.
- Due date between two dates.
- Assigned to a specific user.

#### Exercise 3.3: Aggregations
Compute the average estimated hours per project, grouped by project, using both ORMs.

#### Exercise 3.4: Pagination
Implement cursor‑based pagination for tasks in a project, returning the next cursor.

#### Exercise 3.5: Transactions
Write a transaction that creates a project, adds three tasks, and logs the action in `activity_logs`. Ensure all or nothing.

#### Exercise 3.6: Benchmarking
Run the benchmark script from Part 3 and record the results. Compare Prisma vs Drizzle.

### Checkpoint
- [ ] All queries return correct results.
- [ ] Transactions work as expected.
- [ ] Pagination handles large datasets.
- [ ] Benchmark results are collected.

### Troubleshooting Tips
- If a query is slow, check the generated SQL and use `EXPLAIN`.
- For Drizzle, `with` relations can be tricky; ensure your relations are defined correctly.
- For Prisma, eager loading with `include` can be slow on large datasets – consider `select` with nested includes.

### Reflection Question
Which ORM's query API felt more natural to you? Where did you find yourself reaching for raw SQL?

## Troubleshooting Guide (Quick Reference)

| Problem | Possible Cause | Solution |
|---------|----------------|----------|
| Prisma generate fails | Schema syntax error | Validate with `prisma validate` |
| Drizzle `drizzle-kit` not found | Missing dependency | Install `drizzle-kit` globally or locally |
| Connection refused (PostgreSQL) | Docker not running or port conflict | Start Docker; check port `5432` is free |
| Migration conflict in Prisma | Shadow database mismatch | Reset shadow database or recreate |
| Drizzle migration snapshot out of sync | Manual DB changes | Delete snapshot and regenerate |
| Cold start too high (Prisma) | No Accelerate | Enable Prisma Accelerate |
| Cold start too high (Drizzle) | Using TCP driver in edge | Switch to HTTP driver |
| Query slow | Missing index | Add appropriate index using `EXPLAIN` |
