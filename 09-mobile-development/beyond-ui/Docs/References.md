## R.7 Best Practices & Guidelines

### Mobile Development Best Practices

| Resource | Description |
|----------|-------------|
| Define app purpose and audience | Start with clear objectives before coding  |
| Choose the right approach | Native vs hybrid vs cross-platform decision matrix  |
| Follow platform-specific UI guidelines | Material Design for Android, HIG for iOS  |
| Build secure, performant code | Use MVVM or Clean Architecture patterns  |
| Test throughout the lifecycle | Test early and often  |

### Architecture Best Practices

| Practice | Description |
|----------|-------------|
| Separation of concerns | Keep UI, domain, and data layers separate  |
| Repository pattern | Abstraction layer for data sources  |
| Dependency injection | Manage dependencies for testability  |
| Offline-first design | Prioritize local data before remote  |

## R.8 Quick Reference Card

### Key Commands

```bash
# Project Setup
npx create-expo-app my-app --template
npx expo start
npx expo start --ios
npx expo start --android

# Builds
eas build --platform ios --profile production
eas build --platform android --profile production
eas build --platform all --profile production

# Submissions
eas submit --platform ios
eas submit --platform android
eas submit --platform all

# Updates
eas update --branch production --message "Update message"

# Testing
npm test
npm run test:coverage
npm run test:e2e

# Code Quality
npm run lint
npm run format
npx tsc --noEmit

# Database (Supabase)
supabase start
supabase db diff
supabase db push
```

### Development Lifecycle

- **Inspiration:** Define the app's purpose and audience 
- **Design:** Create UX mockups and wireframes 
- **Development:** Build features using chosen architecture 
- **Stabilization:** Test and fix issues 
- **Deployment:** Release to app stores 
- **Maintenance:** Update and improve 

### Mobile App Success Factors

- User experience at the core
- Platform-specific design
- Responsive layouts for all screens
- Accessibility features (VoiceOver, TalkBack, contrast ratio ≥ 4.5:1) 
- Security built in, not added later
