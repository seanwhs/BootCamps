# PART 1: OFFICIAL DOCUMENTATION

## Model Context Protocol (MCP)

### Official Specification
The MCP specification is the authoritative source for protocol details, including all message types, capabilities, and transport mechanisms .

| Resource | URL | Description |
|----------|-----|-------------|
| **MCP Specification** | https://modelcontextprotocol.io/specification | Complete protocol specification |
| **Server Concepts** | https://modelcontextprotocol.io/docs/learn/server-concepts | Understanding MCP servers, tools, resources, and prompts  |
| **Resources Specification** | https://modelcontextprotocol.io/specification/2025-06-18/server/resources | Detailed resource specification with URI schemes and subscriptions  |
| **GitHub Repository** | https://github.com/modelcontextprotocol | Official MCP GitHub organization |

### Key Protocol Concepts

**What is MCP?**
MCP is an open protocol that standardizes how applications provide context to LLMs. Think of it like a "USB-C port for AI applications" .

**Core Server Features**
Servers provide functionality through three building blocks :

| Feature | Explanation | Examples |
|---------|-------------|----------|
| **Tools** | Functions your LLM can actively call | Search flights, send messages, create calendar events |
| **Resources** | Passive data sources providing read-only access | File contents, database schemas, API documentation |
| **Prompts** | Pre-built instruction templates | Plan a vacation, summarize meetings, draft an email |

**Resources**
Resources are application-driven, giving them flexibility in how they retrieve, process, and present available context :
- Resources support two discovery patterns:
  - **Direct Resources**: Fixed URIs (e.g., `calendar://events/2024`)
  - **Resource Templates**: Dynamic URIs with parameters (e.g., `travel://activities/{city}/{category}`)
- Parameter completion is supported (typing "Par" suggests "Paris" or "Park City")

## Agent-to-Agent (A2A) Protocol

### Official Specification
The A2A protocol enables discovery and communication between autonomous AI agents .

| Resource | URL | Description |
|----------|-----|-------------|
| **A2A Specification** | https://a2a-protocol.org/v0.3.0/specification/ | Complete protocol specification  |
| **What's New in v1.0** | https://a2a-protocol.org/dev/whats-new-v1/ | Migration guide from v0.3.0 to v1.0  |
| **GitHub Repository** | https://github.com/Aganium/a2a-protocol | A2A protocol specification with `agent://` URI scheme  |

### Key Protocol Concepts

**Core Concepts Summary** :

| Concept | Description |
|---------|-------------|
| **A2A Client** | Application that initiates requests to an A2A Server |
| **A2A Server (Remote Agent)** | Agent exposing an A2A-compliant HTTP endpoint |
| **Agent Card** | JSON metadata describing identity, capabilities, skills, endpoint |
| **Message** | Communication turn with a `role` (`user` or `agent`) |
| **Task** | Fundamental unit of work with a unique ID and state lifecycle |
| **Part** | Smallest content unit (`TextPart`, `FilePart`, `DataPart`) |
| **Artifact** | Output generated by the agent (document, image, structured data) |
| **Streaming (SSE)** | Real-time incremental updates via Server-Sent Events |
| **Push Notifications** | Asynchronous updates via webhook |

**Supported Transport Protocols** :
- **JSON-RPC 2.0 Transport** — Primary data format with `application/json` Content-Type
- **gRPC Transport** — Protocol Buffers service definition (`a2a.proto`)
- **HTTP+JSON/REST Transport** — RESTful URL patterns with appropriate HTTP verbs

**Agent URI Scheme** :
```
agent://name
```
- Scheme: `agent://` (always lowercase)
- Name: 2-50 characters, lowercase alphanumeric + hyphens
- Examples: `agent://search`, `agent://assistant`, `agent://code-reviewer`

**Key v1.0 Changes** :

| Change | v0.3.0 | v1.0 |
|--------|--------|------|
| **Operation Names** | `message/send` | `SendMessage` |
| **Enums** | `kebab-case` | `SCREAMING_SNAKE_CASE` with `TASK_STATE_` prefix |
| **Part Structure** | Separate `TextPart`, `FilePart`, `DataPart` | Unified `Part` message with `oneof` content |
| **Task IDs** | Compound IDs (`tasks/{id}`) | Simple UUIDs |
| **HTTP URLs** | `/v1/message:send` | `/message:send` |
| **Agent Card** | `supportsAuthenticatedExtendedCard` top-level | Moved to `capabilities.extendedAgentCard` |

# PART 2: SDKs AND LIBRARIES

## Official MCP SDK

### @modelcontextprotocol/sdk

The official TypeScript SDK for MCP .

**Installation:**
```bash
npm install @modelcontextprotocol/sdk
```

**Quick Start Example** :
```typescript
import { McpServer, ResourceTemplate } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({ name: "Demo", version: "1.0.0" });

// Add an addition tool
server.tool("add",
  { a: z.number(), b: z.number() },
  async ({ a, b }) => ({
    content: [{ type: "text", text: String(a + b) }]
  })
);

// Add a dynamic greeting resource
server.resource(
  "greeting",
  new ResourceTemplate("greeting://{name}", { list: undefined }),
  async (uri, { name }) => ({
    contents: [{ uri: uri.href, text: `Hello, ${name}!` }]
  })
);

const transport = new StdioServerTransport();
await server.connect(transport);
```

**Core SDK Concepts** :

| Concept | Description |
|---------|-------------|
| **McpServer** | Core interface to the MCP protocol |
| **Resources** | Expose data (similar to GET endpoints) |
| **Tools** | LLM actions with computation and side effects |
| **Prompts** | Reusable templates for LLM interactions |

**Transport Options** :
- **stdio** — For command-line tools and direct integrations
- **Streamable HTTP** — For remote servers (supports session management or stateless)

### @openai/agents

The OpenAI Agents SDK for building multi-agent workflows in JavaScript/TypeScript .

**Installation:**
```bash
npm install @openai/agents zod
```

**Core Concepts** :

| Concept | Description |
|---------|-------------|
| **Agents** | LLMs configured with instructions, tools, guardrails, and handoffs |
| **Sandbox Agents** | Agents paired with a filesystem workspace and sandbox environment |
| **Realtime Agents** | Low-latency voice agents with tools, guardrails, and handoffs |
| **Agents as tools / Handoffs** | Delegating to other agents for specific tasks |
| **Tools** | Functions, MCP, hosted tools |
| **Guardrails** | Configurable safety checks |
| **Human in the loop** | Built-in human involvement mechanisms |
| **Sessions** | Automatic conversation history management |
| **Tracing** | Built-in tracking of agent runs |

**Supported Environments** :
- Node.js 22 or later (full support)
- Deno (full support)
- Bun (full support)
- Cloudflare Workers (experimental, with `nodejs_compat`)

**Quick Start Example** :
```typescript
import { Agent, run } from '@openai/agents';

const agent = new Agent({
  name: 'Assistant',
  instructions: 'You are a helpful assistant',
});

const result = await run(agent, 'Write a haiku about recursion in programming.');
console.log(result.finalOutput);
```

### agent-framework-js

A modular, tree-shakeable framework for building and orchestrating AI agents in browser, edge, and Node environments .

**Installation:**
```bash
npm install agent-framework-js
```

**Features** :

| Area | Description |
|------|-------------|
| **Agents** | Text + multimodal input, streaming, reasoning field, threads |
| **Providers** | Copilot + OpenAI-compatible; caller-injected credentials |
| **Tools** | Local function tools, JSON-Schema validation, namespacing |
| **MCP** | Remote (HTTP/SSE) with custom headers; stdio in Node only |
| **Skills** | Progressive disclosure; client-side keyword index |
| **Workflows** | Sequential/concurrent/handoff/group; HITL; checkpoints |
| **Middleware** | Request/response pipeline |
| **Persistence** | In-memory + browser (localStorage/IndexedDB) |
| **Observability** | OpenTelemetry spans with secret redaction |
| **Declarative** | YAML or JSON agent definitions |

**Quick Start Example** :
```typescript
import { createAgent, createOpenAICompatibleProvider } from "agent-framework-js";

const provider = createOpenAICompatibleProvider({
  baseUrl: "http://localhost:1234/v1",
  getCredential: () => process.env.LMSTUDIO_KEY ?? "",
  capabilities: { model: "local-model", maxInputTokens: 262144, maxOutputTokens: 32000 },
});

const agent = createAgent({ name: "Helper", instructions: "Be concise.", provider });
const res = await agent.run("Say hello.");
console.log(res.status, res.output);
```

# PART 7: SECURITY AND BEST PRACTICES

## Authentication Methods

### A2A Authentication 

| Method | Description |
|--------|-------------|
| **Bearer Token** | Standard JWT-based authentication |
| **API Key** | Simple key-based authentication |
| **OAuth2** | Authorization Code flow with PKCE |
| **HTTP Basic** | Basic authentication |
| **mTLS** | Mutual TLS for enterprise deployments |

### A2A Agent Card Security 

Agent Card signature verification uses:
- JWS (RFC 7515)
- JSON Canonicalization (RFC 8785)

### Authentication Example (CrewAI) 
```python
from crewai.a2a import A2AClientConfig
from crewai.a2a.auth import BearerTokenAuth

agent = Agent(
    role="Secure Coordinator",
    goal="Coordinate tasks with secured agents",
    backstory="Manages secure agent communications",
    llm="gpt-4o",
    a2a=A2AClientConfig(
        endpoint="https://secure-agent.example.com/.well-known/agent-card.json",
        auth=BearerTokenAuth(token="your-bearer-token"),
        timeout=120
    )
)
```

## Best Practices

### MCP Server Best Practices
1. **Validate all input** with Zod schemas
2. **Prevent path traversal** with path normalization
3. **Use parameterized queries** for database operations
4. **Implement rate limiting** for production
5. **Log all requests** with structured logging
6. **Use environment variables** for configuration
7. **Implement health checks** for monitoring

### A2A Agent Best Practices 
1. **Set appropriate timeouts** based on expected response times
2. **Limit conversation turns** using `max_turns`
3. **Implement fail-fast or fail-soft** based on requirements
4. **Use streaming for real-time updates**
5. **Configure push notifications** for long-running tasks

# PART 9: TROUBLESHOOTING QUICK REFERENCE

## Common Issues & Solutions

### Connection Issues
| Issue | Solution |
|-------|----------|
| Connection refused | Check server is running, port is accessible |
| Connection timeout | Check network, increase timeout |
| Connection reset | Check for server crashes, restart |

### JSON-RPC Issues
| Issue | Solution |
|-------|----------|
| Parse Error (-32700) | Validate JSON format, check for trailing commas |
| Method Not Found (-32601) | Check method name spelling, ensure registered |
| Invalid Params (-32602) | Check parameter types, validate with Zod |

### Tool Issues
| Issue | Solution |
|-------|----------|
| Tool Not Found (-32001) | Ensure tool is registered, check name spelling |
| Tool Execution Error (-32004) | Check tool implementation, handle errors |
| Tool Timeout | Increase timeout, optimize tool logic |
